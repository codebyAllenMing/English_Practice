SQLite 資料庫設計

語言影子練習 — 索引與關聯層(檔案仍是內容的唯一真相)· 系統架構 · 資料層目的

SQLite(rusqlite bundled) WAL 模式 PRAGMA user_version 遷移 FTS5 全文檢索 表 PascalCase・欄位 camelCase

設計原則

四條原則決定了所有表的形狀;違反任何一條的設計都會在重建或擴充時付出代價。

檔案 = 內容真相mp3 / word.txt / correction.json / analysis.json 留在資料夾;DB 只存索引、關聯與使用者行為
表分兩類可重建(derived):掃資料夾即可重灌。不可重建(primary):使用者行為產生,DB 即唯一真相
自然鍵防孤兒primary 表以 (language, folder) 指回集數,不綁 Episodes.id——重建後 id 改變也不會斷鏈
加法優先新需求=加欄位/加表/加 index,不改既有欄位;SRS 等未來欄位刻意不進 v1

實體關聯圖

上半綠區可隨時砍掉重建;下半紫區是使用者資產,重建流程完全不碰。

欄位定義

Episodes 可重建

每集一列的索引;真相在資料夾結構與檔案,所有欄位可由掃描推導(sourceUrl 例外,見說明)。

欄位型別功能
idINTEGER PK內部流水號,只給 Lines join 用(兩表同屬可重建區,一起重灌所以安全)
languageTEXT NOT NULL課綱語系 en / ja,對應 podcasts/<lang>/ 路徑段
folderTEXT NOT NULL集資料夾名;UNIQUE(language, folder) 即對外自然鍵
titleTEXT顯示標題(目前=folder;保留給日後存 YouTube 原始標題)
sourceUrlTEXT來源影片網址。目前只在 log,下載完成時要順手入庫;重建時撈不回,允許空
statusTEXTdownloaded → transcribed → corrected → analyzed;由檔案存在性推導的快取(mp3 / word.txt / correction.json / analysis.json),列表頁免掃檔案
durationSecREAL音檔長度;轉譯時 whisper 已知,順手入庫
speakersTEXT(JSON)correction.json 講者摘要快取,清單頁顯示用
createDate / updateDateTEXT(ISO)建檔 / 異動時間

Lines 可重建

word.txt 的逐句鏡射;校正完成後整批重灌。lineNo 與 word.txt / 講義 / 生字錨定完全對齊。

欄位型別功能
idINTEGER PKFTS5 external-content 需要的 rowid 錨
episodeIdINTEGER FK歸屬集數(ON DELETE CASCADE)
lineNoINTEGER1-based;UNIQUE(episodeId, lineNo)。全系統行號的共同座標
speakerTEXT講者名(校正後的真名)
contentTEXT內文(去 [Speaker]: 前綴)

LinesFts FTS5 虛擬表

跨集全文檢索(「thunder 在哪幾集出現過」→ 點結果跳練習頁該句)。external content 指向 Lines,以 trigger 同步;tokenizer 用 trigram——unicode61 不切 CJK,trigram 讓日文/中文子字串搜尋直接可用,英文亦可。

VocabItems primary・生字本

練習中手動標記 + 講義匯入的單字;之後的間隔複習、匯出都長在這張表上。

欄位型別功能
idINTEGER PK
language / folderTEXT自然鍵指回集數;集數重建、id 改變都不受影響
lineNoINTEGER出處句(點 → 跳練習頁該句)
termTEXT NOT NULL單字 / 片語
readingTEXT讀音(ja 用;en 空)
meaningTEXT解釋;手動標記時可從講義 vocab 帶入,或留空後補
sourceTEXTuser(手動標記)/ analysis(講義匯入);「AI 挑的 ∩ 我標的 = 重點複習區」疊顯靠它
syncedINTEGER 0/1outbox 旗標;日後匯出 / 外部同步用,現階段先躺著
addedDateTEXT(ISO)標記時間

※ SRS 欄位(dueDate / interval / ease)刻意不進 v1;間隔複習成立時走 migration 加法。

Messages primary・tutor 對話

依集隔離的 AI 問答紀錄——「不會很泛」的邊界;跨 session 保留,下次練同一集 bot 記得你問過什麼。

欄位型別功能
idINTEGER PK
language / folderTEXT自然鍵指回集數
roleTEXTuser / assistant
contentTEXT訊息內容
anchorLineINTEGER提問當下停在哪句——bot 回答「這裡為什麼…」時「這裡」的所指
createDateTEXT(ISO)
Tutor bot 的讀取規則(每次提問的 context 組裝)
來源層提供什麼
word.txt檔案整集逐字稿全文塞進 prompt(6~8k tokens,不做 RAG——全文比檢索準;API 模式當固定前綴吃 prompt caching)
analysis.json檔案講義(大綱+詞彙)——bot 開口即精準,不重新理解本集
anchorLine前端當下目前停在哪句,「這句」有所指
Messages(本集)DB歷史問答——多輪連貫 + 跨 session 記憶
VocabItems(選讀)DB你標過的生字——個人化,照顧弱點

寫入僅 Messages(一問一答各一列,含 anchorLine)。刻意不讀:音檔、其他集逐字稿——對話依集隔離,跨集感知日後走 FTS 查詢工具而非塞 context。呼叫走與校正/講義同一套 llm_via_api / llm_via_cli 雙模式。

Lookups 快取・migration v2

點詞即查的結果快取:AI 對「這個詞在這句裡」的詞性+繁中釋義,一詞一次終身免費(收藏與否無關)。以 (language, folder, lineNo, term) 為鍵——同詞不同句允許不同語境解釋。ja 的詞性另有本地 lindera 即顯(term_pos),不佔此表。這是第一張由 migration v2 加入的表,驗證了加法優先的遷移紀律。

PracticeSessions primary・練習履歷

欄位型別功能
idINTEGER PK
language / folderTEXT練了哪集
startDate / endDateTEXT(ISO)一次練習的起訖;連續天數 / 週統計的資料源
linesPlayedINTEGER本次播放句次數

LineStats primary・句級統計

欄位型別功能
language / folder / lineNo複合 PK句座標
playCountINTEGER累計播放次數;重播最多 = 難點,聚合出「本集難句 Top N」與跨集弱點清單
lastPlayedTEXT(ISO)最後播放時間

架構決策

落地位置data_dir()/app.db(dev=專案根、release=App Support);WAL 模式;.gitignore 加 *.db。Rust 端 rusqlite(bundled),零系統依賴,延續全靜態哲學
MigrationPRAGMA user_version + 啟動時依序執行(Flyway 同構);每個未來功能 = 遷移 N+1,加法優先
寫入時機下載完成→插 Episodes(含 sourceUrl,補掉現在不落地的缺口);轉譯完成→灌 Lines;校正完成→重灌 Lines + speakers 快取;各步同步更新 status
命名慣例表 PascalCase 複數、欄位 camelCase(.NET 風格);時間一律 ISO 8601 文字

重建流程(保險絲)

DB 損毀或 schema 大改時的逃生路線;primary 四表全程不碰。

掃描podcasts/<lang>/*/
→
清空 derivedEpisodes・Lines・LinesFts
→
回填集數依檔案推導 status / speakers
→
回填逐句word.txt → Lines → FTS
→
完成primary 表原封不動,自然鍵自動接回
