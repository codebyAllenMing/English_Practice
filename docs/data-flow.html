資料層的目的與學習閉環

為什麼要加 SQLite —— 系統架構 · 資料庫設計

目的

現在的 app 只記「內容」——每集的音檔與逐字稿都在,但「你」不在:練了什麼、卡在哪句、 標了哪些字、問過什麼,session 結束就蒸發。資料層的目的是把這些行為變成可累積的資產, 讓工具(單次播放器)升級成學習系統(記得你、回饋你)。

加入前後

現在:檔案系統(只記內容)

  • 每集自成一個資料夾,彼此無關聯
  • 練習是無狀態的:關掉 app,這次練了什麼不留痕跡
  • 生字只能抄在別處;想找「這個字哪集出現過」得逐檔翻
  • 講義、校正各自為政,沒有跨集視角

加入 SQLite:行為與關聯(記住你)

  • 集數/逐句有索引,跨集可查(FTS 全文檢索)
  • 每句播放次數、每次練習起訖都留痕 → 難點浮現
  • 生字有家:出處句、讀音、來源(自標/講義),可複習可匯出
  • tutor bot 有記憶:這集問過什麼、你常卡什麼

三個學習閉環

目的不是「存資料」,是讓資料流回練習——每條流程的終點都指回起點。⛁ = 進資料庫的節點。

① 練習閉環LineStats · PracticeSessions

逐句跟讀play_line
→
行為落庫播放次數 · 練習起訖
→
難點浮現重播最多 = 難句 Top N
→
針對性重練跳難句 · 弱點清單
↩ 回到跟讀
副產品:連續天數、週統計 —— 你要的「版本控制式自我追蹤」的資料源。

② 詞彙閉環VocabItems

遇到生字練習中點標記 / 講義匯入
→
入生字本term · 出處句 · source
→
複習出處原句回放(SRS 為未來遷移)
→
跨集再現「這個字你第 2 集標過」
↩ 加深記憶
「AI 挑的(講義)∩ 我標的(手動)」= 重點複習區 —— source 欄位就是為這個疊顯存在。

③ 問答閉環Messages

練到卡住「這句為什麼這樣用?」
→
提問落庫anchorLine 記住你在哪句
→
bot 精準回答講義+全文+當前句 context
→
累積個人檔常問時態?常卡敬語?
↩ 回答越來越貼
對話依集隔離(不會很泛),跨 session 保留(下次練同一集,bot 記得上次卡哪)。讀取規則:word.txt 全文 + analysis.json 講義 + anchorLine + 本集 Messages(+ 選讀 VocabItems);詳見 資料庫設計 Messages 區。

解鎖的功能地圖

同一套 schema,功能按依賴順序長出來;每一階都是前一階的加法,不用改地基。

近端(schema 落地即有)

  • 生字本 — 練習中標記、講義匯入、出處跳轉
  • pipeline 狀態快取 — 清單頁免掃檔案
  • tutor bot 記憶座 — Messages 表先就位

中端(資料開始累積後)

  • 跨集全文檢索 — FTS5:「thunder 在哪幾集?」點了跳那句
  • 難句統計 — 本集 Top N · 跨集弱點
  • 練習履歷 — 連續天數 · 週統計
  • 詞彙跨集再現 — 舊生字出現時標亮

遠端(閉環成熟後)

  • 間隔複習(SRS) — 每日待複習隊列 (migration 加欄位)
  • 學習報告匯出 — 週報 CSV / Markdown
  • bot 個人化 — prompt 夾帶你的弱點檔案

邊界(這層「不是」什麼)

不是內容庫音檔、逐字稿、講義永遠住檔案系統;DB 只存索引與行為。內容搬進 DB 的那天,「掃資料夾重建」的保險絲就斷了
不是同步服務單機單人;synced 旗標只是為未來匯出預留的 outbox 位,不預設任何雲端
不是一次到位v1 只建七張表跑近端功能;SRS、報告等靠 user_version 遷移逐步加法,永不重寫
